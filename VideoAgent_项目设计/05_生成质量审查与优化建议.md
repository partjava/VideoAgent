# VideoAgent 生成质量审查与优化建议

审查日期：2026-11-03。范围：任务创建、脚本/分镜/提示词、图片与视频服务、配音字幕、剪辑质检、续跑和前端查看流程，以及现有测试。本文是代码审查与改造建议，未修改生成逻辑。

## 判断与验证边界

项目具备端到端生成骨架，可以沿现有架构优化。当前最主要的缺口是：连续性只有文字描述，没有跨镜头视觉约束；动作节拍只有字符串，没有完整时间校验；画面、声音、字幕使用不同的时间安排；质检不能识别内容质量。

仓库中没有找到可供抽帧复核的 MP4/SRT，因此以下不能当作对历史成片的逐帧诊断。没有调用付费生成服务。执行 `python -m unittest discover -s tests -v` 时，测试在导入阶段因缺少 dotenv、anyio 等依赖报错，不能据此判定业务测试通过或失败。

## 一、直接影响质量的问题

### 1. 镜头连续性没有落实到生成输入（最高优先级）

证据：`agents/image_agent.py` 独立、并行生成各分镜底图，只传提示词、负面词和比例；`services/image/base.py` 没有角色参考图接口。`agents/video_agent.py` 为各镜头独立提交当前底图；`services/video/base.py` 没有尾帧或参考序列接口。

`scene_continuity`、`last_frame_for_transition` 等只是附加文字。上一镜头实际生成的最后一帧，没有进入下一镜头输入。下一镜头也没有经过与上一镜头实际输出的对照。

影响：相同文字不能确保同一张脸、衣服细节、道具位置、朝向、光照或手部姿态一致。

建议：
- 保存全片角色、场景、道具设定，以固定 ID 引用；在分镜和提示词阶段显式传入，避免依赖模型从剧本自行推断。
- 先制作角色参考图和场景参考图，再生成镜头首帧；实际注入方式由各服务的已验证能力决定。
- 区分连续动作、同场景切镜和跨场景切换。连续动作可以使用上一镜头尾帧续接；同场景换机位应结合参考图重新构图，不能把尾帧机械复制到所有下一镜头。
- 有连续依赖的镜头按组生成，互不依赖的组继续并行。
- 保存相邻镜头状态：角色位置、视线、朝向、持物手、道具位置、动作阶段。生成前检查计划状态，生成后检查实际画面。

### 2. 逐秒动作没有可验证的时间结构（最高优先级）

证据：`services/llm/deepseek_service.py` 要求每 0.5–1 秒发生变化，但 `motion_beats` 只要求至少三条字符串；`PromptAgent` 不检查时间覆盖、缺漏、重复、超时或动作冲突；`_build_motion_prompt` 将其直接拼成文本。

影响：十秒镜头也可能只有三条短描述；镜头运动、角色动作、环境变化容易互相抢占。写出时间标签不能证明视频执行了该动作。

建议将节拍改为结构化数据：开始秒、结束秒、角色 ID、动作、动作对象、起始状态、结束状态、镜头变化。验证覆盖整个镜头且无非预期空缺；允许持续动作和有意停顿，不要求每秒换一个动作。

每镜头围绕一个主要动作组织“准备—执行—结果”，辅助表情和环境变化适量加入。先确定动作可见，再扩写文字。图片提示词只能描绘动作开始状态，不能提前画出动作结果。

示例：5 秒镜头，人物右手拿起桌上的信封。

| 时间 | 可见动作 | 状态约束 |
|---|---|---|
| 0–1 秒 | 视线落向信封，右手离开身体侧边 | 信封仍平放桌面 |
| 1–2 秒 | 右前臂向桌面伸出，手指靠近信封右边缘 | 左手保持不动 |
| 2–3 秒 | 拇指与食指捏住边缘 | 信封仍接触桌面 |
| 3–4 秒 | 手腕抬起，信封离桌约十厘米 | 信封不换手、不变形 |
| 4–5 秒 | 信封抬到胸前，视线跟随，动作收稳 | 下一镜头继承右手持信封 |

以上是动作计划示例，具体空间与速度需与构图、首帧和实际模型输出校准。节拍转换成各模型适用的简明提示词，不把所有内部字段原样塞入请求。

### 3. 配音直接拼接导致累计错位（最高优先级）

证据：`agents/editor_agent.py` 将每个分镜音频加入 `audio_segments`，最后 `concatenate_audioclips(audio_segments)`；短音频没有补齐镜头剩余时长，也没有按镜头起点定位。`SubtitleAgent` 则按计划镜头时长累加字幕。

可由代码推导的反例：第一镜头 5 秒、配音 3 秒，第二镜头配音会在全片第 3 秒开始，第二镜头画面和字幕却在第 5 秒开始。后续短音频继续积累偏差；缺配音也会让后续音轨前移。

建议建立唯一时间轴，音频按分镜绝对起点放置。短配音保留余下静音或环境音；长配音先精简文案或调整规划，只允许有限的语速调整，避免无限加速。字幕按实际语音句子边界生成，统一使用最终时间轴。

### 4. 计划时长、生成时长与实际时长不一致（最高优先级）

证据：
- 分镜提示词及校验允许目标时长至目标加 30 秒；30 秒任务可以接受 60 秒分镜。
- 固定要求 6–12 个镜头且每镜头至少 4 秒，未按目标时长和服务上限动态规划。
- Doubao 服务将请求时长截到 4–12 秒，返回元数据仍记录原 duration。
- Wan 服务请求中没有传入 duration，ratio 硬编码为 9:16，忽略传入比例。
- Editor 遇到短于计划的片段只截到 `min(实际时长, 计划时长)`，并不会补足；字幕仍按原计划累计。

建议：为每个服务定义经过验证的时长、比例和分辨率能力；生成前分配可执行镜头，生成后探测实际媒体信息。明确区分计划时长、请求时长、实际时长、剪辑时长。所有字幕与音频从最终剪辑时间轴导出。

### 5. ComfyUI 默认映射与服务传参不匹配（最高优先级）

证据：`services/video/comfyui_video_service.py` 传入 positive_prompt、image_path、duration；`data/comfyui/video_mapping.json` 只有 positive_prompt、negative_prompt、seed、width、height、length、fps。`apply_mapping` 会跳过不存在的映射项。因此仓库当前配置只会应用正向提示词，传入的首帧和时长不会生效。

建议：上传首帧到 ComfyUI 可访问位置，映射到实际图像加载节点；根据工作流规则把秒数转换成合法帧数，并应用比例。缺少必要映射时在提交前报错。不能把任意输出下载后改成 .mp4 就当成合格视频，应检查容器与流信息。

### 6. 角色设定在后续阶段丢失了显式传递

证据：TaskPlanner 生成 characters 和 visual_world；ScriptAgent 将脚本保存为标题、正文等字段；StoryboardAgent 仅传 script；PromptAgent 仅传 scenes、ratio、style。角色设定可能出现在正文里，但没有作为独立、不可变的约束一直传到生成端。

建议：将全片设定独立保存，分镜、提示词都显式读取。固定外貌、服装与道具属性，镜头只描述发生变化的状态。

### 7. 质检不检查内容，重试不能修复源头

证据：QualityAgent 只检查 final.mp4 存在，空文件也满足这个条件。缺文件时抛异常，不返回供条件路由使用的失败结果；正常返回必为 success，因而现有条件分支没有实现预期质量闭环。即使回到 Editor，也无法修复角色变脸或缺动作。

建议两层质检：媒体层检查可解码、时长、比例、音轨、缺镜和字幕范围；内容层通过抽帧/短片分析检查首尾状态、角色道具连续性、动作完成度。抽帧不能证明每个中间动作均完成，需要必要的时间采样。失败定位到具体镜头与环节，只重做受影响部分，限制次数与费用。

## 二、稳定性与可控性问题

1. **重试分支异常处理相反。** `_try_generate` 遇到特定内容拒绝信息直接抛错，上层 `_generate_one` 没有捕获，所以预期的温和改写重试到不了；普通错误返回 None 反而进入该重试。应区分网络、限流、参数、内容拒绝等类型，按服务规则处理；内容调整应保持合规且检查剧情是否改变。
2. **纯文本改写与 JSON 解析冲突。** `_rewrite_prompt` 要求只输出文字，但 `_call_api` 强制 JSON 解析，通常会失败并回退原文。应分开文本和结构化响应接口。
3. **失败镜头被掩盖。** 部分生图失败可继续；Editor 会略过没有素材的镜头，缺图片文件时甚至生成纯色占位图；字幕失败也只记录日志，最后仍可能成功导出。应明确完整、部分完成、失败状态，不能用文件存在代替素材齐全。
4. **缓存没有依赖版本。** 有 image_prompt 就跳过提示词生成；有文件就复用媒体；整体配音存在就跳过分镜音轨检查。上游修改后可能继续使用旧素材。建议保存输入摘要、提示词版本、模型和配置摘要，只失效受影响的下游。
5. **没有任务执行互斥。** run-pipeline 接口可重复触发同一任务，可能重复付费和写入同一路径。应添加任务锁、执行 ID、阶段幂等与服务任务 ID 恢复。
6. **并行汇聚没有显式表达依赖。** pipeline 注释说 subtitle 等待两条分支，实际只有 video → subtitle，没有 voice 与 video 的显式汇聚边。实际调度是否造成问题需要用当前 LangGraph 版本做慢配音/慢视频实验，不能仅凭图断言已经发生竞态；建议明确建立汇聚并测试。
7. **多人声音设定未执行。** 保存 speaker 但所有分镜使用同一 Xiaoxiao 声音，表演情绪没有进入 TTS。应建立角色到声音的固定映射，并支持一个镜头多个带时间的对白片段。
8. **策略冲突。** 脚本要求约 5–6.6 字/秒，分镜要求 3–5 字/秒；对白校验要求最低密度却没有上限，不允许部分合理留白。建议按实际语音时长和剧情节奏校准。漫剧模板建议气泡文字，图片规则又限制文字，宜统一为画面生成不承载字幕、后期排版。

## 三、建议的改造顺序

### 第一阶段：让生成结果可信

修复音频定位与字幕共用时间轴；统一计划和实际时长；修复 ComfyUI 映射与 Wan 参数透传；禁止静默丢镜和占位成功；修复错误分类和重试；增加可解码与素材完整性检查。

验收：两个 5 秒镜头、第一段 3 秒配音，第二段必须从第 5 秒开始；缺音频不会前移后续声音；缺镜头不能报告完整成功；横竖比例正确；首帧和时长确实进入工作流。

### 第二阶段：让剧情和动作可执行

全片角色/场景/道具设定贯穿各阶段；结构化动作节拍与相邻状态；按服务能力规划镜头数量和时长；检查首帧是否满足动作准备条件；分镜生成结果校验唯一 ID、数量、顺序和必需字段；提供局部修复。

验收：动作覆盖镜头时段，起止状态可对照，上一镜头右手拿信封时下一镜头不能突然空手或换手。允许合理停顿。

### 第三阶段：让画面真正连续

参考图注入、镜头分组、连续动作尾帧续接、跨机位重新构图，以及生成后抽帧检查。先用少量短片验证，不直接批量重跑所有历史任务。

### 第四阶段：让用户能低成本调整

前端增加分镜工作台：时间、对白、首帧、动作节拍、上一镜头结尾与下一镜头开头并排查看；支持编辑并单镜重生成，标出需要更新的下游。提供可选的“先预览分镜再生成视频”，保留一键模式。当前页面主要查看输出，没有形成编辑闭环。

## 四、验证与回归建议

固定五类小样：拿起道具、连续走动、双人对话、跨机位同场景、明确跨场景。保持故事和配置一致，对比优化前后，记录角色/道具连续性、动作完成率、时间轴误差、缺镜率、重试次数、费用和耗时。自动评分结合人工检查，不能只靠另一个模型给总分。

现有测试主要覆盖配置、数据库、文案及模拟流程，未覆盖媒体合成时间轴、动作节拍覆盖、实际参数透传和内容质检；`test_fixed_generation_direction.py` 仍断言默认风格包含历史故事，与当前默认漫剧实现不一致，也需更新。

本次未更换模型、未安装项目依赖、未启动外部生成任务。建议先完成第一阶段和结构化分镜，再用同一组短片判断模型或提示词的进一步调整价值。
